# 击球、落点与战术控制规划

> 状态：讨论与验证方案，不代表功能已经实现。本文记录当前代码事实、候选设计和待确认问题，不将未经实测的参数当作最终方案。

## 1. 目标与原则

这个项目首先是一个让玩家在屏幕前**动起来、愿意持续玩**的体感乒乓球游戏。当前整体手感已得到用户认可；后续增加技巧时，应保留轻松上手和现有玩法，而不是为了模拟真实乒乓球而让接球变难。

长期目标是让玩家逐渐感受到「我采取的动作影响了球」，并能体验左右落点、前后落点、快慢和短球等战术。真实击球结果还与来球速度与旋转、球拍运动方向和速度、拍面角度及接触位置等共同有关；横拍和直拍本身是持拍习惯，而不是独立决定弹道的物理参数。

设计原则：

1. **先可控、再丰富、最后追求真实**：同样意图应产生大致相近、可理解的结果。
2. **不破坏已有体验**：新控制先作为可选模式，默认保留旧行为；现有难度、判定和辅助不随之改变。
3. **以普通摄像头可可靠识别的动作作为输入**：不假装能精确测量球拍角度、击球力或球的真实旋转。
4. **动作要适合站在屏幕前运动**：不要求持续大力挥拍、精细手腕动作、看不清的小按钮或危险的前冲。
5. **玩法、输入和物理分层验证**：先证明所需球路可行，再证明人能够稳定发出相应意图；模拟通过不等于摄像头实测通过。

## 2. 当前实现基线

以下事实以当前 `develop` 的代码为准；后续实现后应同步更新本节。

### 玩家输入和击球

- 体感以人体中心横向位置控制球拍，球拍高度自动跟随来球。挥拍检测使用约 180ms 的手腕运动速度和垂直跨度，手腕不可用时可退到肘部；各运动量按人体尺寸归一化，见 [poseTracker.ts](./src/input/poseTracker.ts) 和 [swingDetector.ts](./src/input/swingDetector.ts)。
- 达到速度或垂直跨度阈值即触发挥拍；强度来自两种信号中较强的相对量。这是**动作强度的估计**，并非测量拍面真实力量，且取值发生在触发时，能否稳定区分轻重需要实测。
- 鼠标、键盘挥拍使用固定力度；辅助击球也使用固定力度。球拍走位、挥拍检测和命中判定是不同环节。
- 命中后，左右瞄准点由球拍横向位置、球与拍心的偏差和随机扰动共同决定；前后瞄准点在 `0.45～1.05m` 随机选择。力度经映射影响发球初速，见 [game.ts](./src/core/game.ts) 的 `hitByPlayer`。
- 击球判定有弱、标准、强三档；慢动作改变模拟时间倍率，不等同于单独改变物理球速。

### 轨迹、旋转与对手

- 台面坐标：`X` 为左右，`Z` 从我方指向对手；网在 `Z=0`，对手底线在 `Z=1.37m`。落点左右与前后是两个独立维度。
- `launchTo` 根据目标点和速度计算出射速度，并使用最低过网速度、射程和过网余量等保护；实际模拟另有阻力和碰撞，因此输入的瞄准点**不保证等于实际落台点**，必须用模拟碰撞事件验证。
- 球有 `spin` 数值，玩家击球会给它赋值，但目前物理推进只使其衰减，**没有用旋转改变飞行或落台反弹**；目前不能宣称已经模拟上旋、下旋或侧旋。
- 对手有反应延迟、左右移动、瞄准误差及概率漏接；其球拍前后位置基本固定。直接增加短球可能让球在对手够到前二次落台，造成不合理的必得分。
- “对手来球击球位置”三档约束的是对手回球和标准模式对手发球抵达我方拍面时的预测横向位置，不是我方回球落点范围。
- 击球提示带、软吸附共用轨迹预测；辅助移动和辅助击球可以独立开启。引入新弹道后必须确认这些机制仍与真实轨迹一致。

## 3. 需要区分的概念

| 概念 | 含义 | 现状及注意事项 |
| --- | --- | --- |
| 命中位置 | 球相对球拍的位置 | 与左右回球方向有关，也参与命中判定 |
| 击球时机 | 玩家挥拍与来球到达之间的关系 | 影响能否命中；不要把识别阈值等同于命中窗口 |
| 落点左右 | 球首次落在对手半场的横向位置 | 目前受命中偏差和随机扰动影响 |
| 落点前后 | 首次落台靠网或靠底线 | 目前随机；需要看实际碰撞位置而非仅看目标值 |
| 球速 | 球的物理运动速度 | 目前受估算力度影响；与全局时间倍率不同 |
| 短球 | 通常落在对手近网处并形成较难上手的后续轨迹 | 不等于“球速慢”或“瞄准点靠网”；还需考虑过网高度、反弹及对手是否能上前接 |
| 拍面角度、旋转 | 真实技术中的重要因素 | 当前普通摄像头方案不能可靠获取拍面姿态，物理也未实现旋转效果 |

上表讨论的是**我方回球在对方台面的落点**。它不同于“对手来球经过我方球拍平面时的位置”，也不同于球拍自身的前后位置。

## 4. 体验设计：从意图到结果

建议将未来流程理解为：

```text
玩家动作 / 键鼠输入
    → 挥拍识别与质量判断
    → 玩家意图（例如左右、前后、快慢）
    → 回球目标与少量受控误差
    → 真实物理模拟与碰撞结果
    → 对手反应、得分及反馈
```

“意图”是帮助玩家控制游戏的抽象，不表示摄像头测得了真实球拍朝向或物理力量。结果允许受到来球、命中位置及少量误差影响，但同样的有效输入不应因为随机扰动而经常得到相反的结果。

### 建议的体验层级

| 层级 | 目的 | 控制方式 | 状态 |
| --- | --- | --- | --- |
| 现有模式 | 保留已认可的运动与对打体验 | 现有走位、挥拍和随机落点 | 已有，继续作为默认 |
| 前后控制体验 | 先体验短、中、深落点 | 候选：根据已识别的挥拍强弱倾向选择前后落点 | 待验证；不等于真实技术模型 |
| 多维战术控制 | 玩家分别影响左右和前后 | 根据识别实验选择可靠动作或其他输入 | 待设计，不预设手势 |
| 进阶球路 | 体验旋转、削球、拉球等 | 取决于输入可靠性和简化物理效果 | 远期研究，不承诺实现 |

轻挥偏短、快挥偏深仅是**低门槛候选映射**：它把球速和落点耦合，不能表达所有真实球路。若识别结果不稳定、需要过度用力，或玩家觉得不自然，就不应作为默认方案；短球也不能仅靠降低速度实现。

### 随机性

- 现有模式不调整随机数调用顺序和球路，以固定种子对比保护兼容性。
- 新模式中，随机误差应围绕玩家意图而不是覆盖意图；具体误差区间须根据识别数据和试玩确定。
- 不通过人为修改比分或强行让对手失误来表现“好球”。球能否接到应与轨迹、规则、对手位置和能力相符。
- 对手的现有概率漏接暂时保留；将来可单独评估如何把更多失误归因于实际到位情况，不能与第一阶段的落点实验混在一起。

## 5. 控制方式与识别约束

### 体感候选

1. **挥拍强度**：优先测量现有强度输出的分布，分别采样自然轻挥、中挥、快挥，不要求用力。重点检查首次越过阈值时的取样是否都挤在低值、不同距离及腕/肘切换是否一致。
2. **横向挥拍方向**：以后可研究击球附近的动作方向，但引拍和随挥可能互相抵消或反向。需要比较不同时间窗口和判定延迟，不能把整段路径长度误当作方向。
3. **前后动作**：单摄像头的深度和拍面朝向不可靠；暂不把向摄像头前后伸手或身体前冲作为必要操作。
4. **不可识别时**：继续保留已有挥拍和身体移动能力；新意图在低可信度时采用清楚、稳定的中性策略，具体策略和提示须在原型阶段确定，不应悄悄把识别失败伪装成精准控制。

任何动作映射都需考虑左手、右手、双手、画面镜像、身体走位与挥拍同时发生、动作幅度差异、遮挡、低帧率和肘部兜底。镜像方向应以玩家看到的画面为准，不能假设左右手使用同一符号。

### 鼠标和键盘

这两种输入是独立的可访问方式，不应因为加入体感技巧而失效。前后与左右控制可研究按键、鼠标或明确的设置选项，但不要占用当前走位、挥拍和暂停操作；交互方案需要实际选择和验证，暂不预设为正式默认键位。

### 校准和反馈

- 先尝试无需复杂标定的方案；必要时提供可跳过、可重做的轻量校准。
- 不依赖显示过多数值或遮挡画面的悬浮提示。调试信息可放在设置或开发界面；比赛中应以球的实际行为和简洁、可关闭的反馈为主。
- 照顾不同活动能力：允许关闭技巧控制、调整识别灵敏度，并继续支持现有辅助移动、辅助击球、软吸附和慢动作。

## 6. 前后落点与短球技术方案

### 6.1 先建立可行轨迹库

在修改玩家操作前，通过固定击球状态和物理模拟，对候选目标及速度进行网格测试，记录首次对方落台、是否触网或出界、过网高度、反弹轨迹及第二落点。按实际落台位置划分“短／中／深”；分区边界先作为实验参数，待体感与战术测试后确定。

重点确认：

- 当前 `5.0～6.2m/s` 的玩家初速范围、过网速度下限和射程修正是否允许可用的近网球；不能仅把目标 `Z` 改小就宣称能放短。
- 短球也要合法过网并落在对手半场；球落台后能否再次落在台内、何时到达对手可接区域，应由模拟结果决定。
- 考虑不同来球高度、横向位置、力度和当前命中容错。不可解的目标须明确归类，不能静默伪造落点或宣称成功。
- 使用相同固定步长及 `stepBall` 验证；显示目标、预测轨迹、实际碰撞和最终计分必须一致。

如果现有 `launchTo` 无法形成需要的短球，先评估受控调整初速和弧线、必要时扩展求解器；不得通过无条件传送球或绕过网与落台判定实现。回球能否合法不应被保证到掩盖所有失误。

### 6.2 控制落点

可选模式将输入映射成一段目标区域或连续深度，而不是无依据地锁定一个精确点。比较短、中、深时，记录实际落台分布和不合法球；左右目标、力度与深度之间的耦合和误差需要明确。玩家已经击出的球不会因中途切换设置改变。

### 6.3 对手接短球

在真实短球进入正式玩法前，评估并实现与之匹配的对手前后移动或可接触范围：

- 从球的预测轨迹、当前身体/拍面位置、反应延迟和速度推导能否接球；结合已有横向移动，不瞬移到球前。
- 对手上前后需要合理回位，并保证球拍、人物动画与判定位置一致。
- 不同难度使用可解释的到位能力，既不能所有短球必得分，也不能让对手永远无解地接到；是否调整概率漏接另行决定。
- 覆盖台内二次落台、触网、出界、双方计分，以及休闲和标准规则。

如果对手前后移动暂不可用，则短球只用于明确标识的实验/练习，不应包装成完整对抗玩法。

## 7. 可选的后续战术

### 左右方向

先证明玩家能稳定表达左右意图，再以落点分布检验结果。需要区分玩家身体移动造成的球拍位置变化和手臂挥动方向，避免走位时误触发方向。无可信方向时采用稳定中性策略；边界球和拍面偏差仍应有合理作用。

### 速度与落点独立

一旦前后落点控制可靠，再研究让速度和落点分别控制，支持“较快的短球”或“较慢的深球”等组合。不要把轻挥短、快挥深作为不可改变的物理事实。不同输入方式不一定需要相同手势，但应能获得可解释的体验。

### 旋转与拍面角度

旋转属于后续独立课题。可研究用简化的击球类型意图选择上旋、下旋或侧旋，再让统一的球体推进及落台反弹体现效果；不能仅修改视觉或 `spin` 字段就称作完成。

引入旋转时需同步更新轨迹预测、提示带、软吸附、对手预判、来球范围约束、发球与碰撞测试，并保证固定步长和数值稳定。真实拍面角度追踪需要额外可靠输入或设备，现阶段不作承诺。

## 8. 实施顺序与退出条件

每阶段先评审结果再决定是否继续；阶段名称不是工期承诺。

| 阶段 | 交付与验证 | 进入下一阶段的条件 |
| --- | --- | --- |
| 0. 基线 | 固定种子回归；记录现有强度分布、实际落点、合法率和对手接球；真实摄像头轻／中／快挥体验 | 能解释当前输出；明确摄像头和动作条件；不改变现有玩法 |
| 1. 球路实验 | 离线模拟短／中／深实际落台及可接性，明确轨迹可行域和失败原因 | 实际落点有可区分区域，合法性与规则一致；不可解情况有明确处理 |
| 2. 可选前后控制 | 接入经验证的输入映射，保留原模式和独立设置；提供非侵入式反馈 | 真实试玩能重复控制落点，运动舒适；旧模式固定种子和事件流不变 |
| 3. 对手前后接球 | 实现前后到位和回位，完善动画与规则 | 短球不是必得分；难度差异可解释，无穿模、瞬移或规则回归 |
| 4. 左右及独立快慢 | 对比候选输入方式，分离玩家意图和随机误差 | 各方向意图可重复识别；无方向时回退行为明确；输入方式均可玩 |
| 5. 旋转等进阶 | 先单独验证简化物理及反馈，再决定接入对抗 | 真实轨迹与预测一致，规则、性能及用户体验均通过验证 |

第 1、2 阶段的先后与第 3 阶段的上线方式取决于球路实验：若短球需要对手上前才能公平对抗，正式启用短球必须等对手能力完成；可以先在练习中测试轨迹。

## 9. 验证方案

### 自动化

- **默认兼容**：同一固定种子、输入和时间步，对比新功能关闭前后的事件、比分与弹道；不能额外消耗随机数改变旧模式。
- **物理及分布**：对多种击球位置、高度、来球、目标和力度，测量实际首次落台而非目标参数；覆盖中心、边线、网、底线以及不可解组合。对可达的短、中、深样本，检查实际落点属于对应实验区域，记录触网、出界和失误。
- **控制有效性**：固定其余条件，改变一个意图；检查目标区域与实际落点分布向预期方向变化。重复输入和固定种子应可复现；测量随机误差相对于分区宽度的影响。
- **识别边界**：手腕/肘部切换、缺帧、姿态丢失、左右手、镜像、低运动量、走位与挥拍同时发生、冷却和连续挥拍。
- **对手与规则**：短球可接、够不到、二次落台、回位、触网、出界；两种规则、各难度、发球及得分。
- **辅助与切换**：提示带和软吸附预测与实际轨迹一致；自动移动、自动击球、慢动作及三档来球范围正常；切档只影响后续约定的挥拍/击球，不改已飞出的球。
- **性能与稳定性**：在目标设备上比较启用前后的帧率和输入延迟；采样、预测和粒度不得造成明显卡顿，非有限数与不可达轨迹应在测试中暴露。

执行现有 `npm run build`、`npm run test:game`、`npm run test:physics`、`npm run test:input` 和 `npm run test:view`；为新增或修复的行为补充针对性测试。

### 真实体验

- 在常见屏幕前、不同站位距离和光照下，以自然轻／中／快动作重复试玩；分别观察左右手、手腕遮挡及肘部兜底。
- 分别记录挥拍触发率、轻重意图区分率、目标区域内实际落台比例、触网/出界比例、对手接球情况和延迟感受。
- 对比旧模式与体验模式，询问是否更容易理解、是否仍有运动乐趣、是否需要刻意猛挥、是否觉得结果可控。
- 这些指标及样本量先用于建立基线；正式验收阈值在了解真实设备和玩家数据后共同确定，不以自动模拟命中率代替人的体验。
- 摄像头画面及动作数据默认不保存、不上传；若确需录制用于调试，应先获得明确同意并说明用途。

## 10. 待共同决定的问题

1. 前后控制体验是优先做成单独练习，还是同时用于正式对局？如果正式对局，需要先解决短球公平性。
2. 强弱与前后暂时耦合是否可接受？若识别不稳定，是否改用明确但独立的输入方式？
