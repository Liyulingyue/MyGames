# 乒乓球游戏体验优化建议

本文记录体验优化方案。**明亮场馆、环境切换、首页设置、设置暂停、返回首页和手动击球辅助已实施。** 下文中的「现状」指方案提出时的代码状态。

## 1. 明亮的乒乓球室

### 现状

- [scene.ts](./src/render/scene.ts) 使用深色背景、雾和地板，整体更像暗色舞台；场景目前也没有明确的墙面、场馆标识等室内元素。
- [renderer.ts](./src/render/renderer.ts) 使用固定曝光，尚无场景主题设置。
- 台面、球和球拍是独立模型；只提高曝光不一定能产生真实的明亮球室观感，也可能降低白球与背景的对比度。

### 建议方案

1. 增加「明亮球室」环境：浅色墙面、明亮均匀的室内灯光、适度暖色的地板，保留清晰的球台与白球对比。
2. 保留现有暗色环境作为「夜间球场」，在游戏内「设置 → 画面」切换；建议默认明亮环境。
3. 环境切换只影响渲染，不改变物理、相机位置或对局状态；新开一局及返回首页后再次进入时沿用当前选择。
4. 控制额外几何体、灯光及阴影开销，切换和退出时释放相关资源，不重复创建渲染器。

### 验证要点

- 明暗环境均可实时切换；球、球拍、球网和台线在常见屏幕及相机设置下清晰可辨。
- 桌面及窄屏截图对比，并检查过曝、白球融入背景和 HUD 遮挡问题。
- 连续切换环境、返回首页并重新进入，确认资源不持续增长；对比切换前后帧率，避免明显下降。

## 2. 设置与返回首页

### 现状

- 对局中右上角已有齿轮按钮，可打开包含操作、手感、画面、辅助和声音的设置面板，见 [App.tsx](./src/App.tsx)。
- 目前「返回主菜单」只出现在结算页；对局进行中没有返回入口。`Esc` 在对局中仅用于关闭已打开的设置。
- 结算页返回首页会重置 HUD；姿态追踪器只在组件卸载时关闭，返回首页后可能仍保持摄像头开启。下一次进入时需要核对摄像头状态与实际设备是否一致。
- 打开设置时游戏仍在进行；开始界面有模式选择，但没有完整的对局设置。

### 建议方案

1. 保留右上角齿轮，增加清晰可见的「设置」文字或辅助提示，避免仅凭图标难以发现。
2. 在设置面板靠前位置提供「返回首页」，对未结束的比赛先提示当前比分和对局进度将丢失；玩家确认后退出，取消则回到原比赛。
3. 建议打开设置或退出确认时暂停模拟，关闭或取消后恢复，避免玩家操作面板时丢分。确认页须支持键盘、焦点管理与 `Esc`。
4. 返回首页时明确摄像头策略：建议停止采集，并在再次选择体感模式时重新请求或恢复采集；须处理正在初始化时退出、延迟授权和失败等情况。
5. 如需在首页预先调整难度、环境和辅助，可增加「游戏设置」入口并复用同一组设置，不要维护两份独立状态。是否提供完整设置留待确认。

### 验证要点

- 对局中能发现设置和返回入口；退出确认的取消、确认均符合提示，不会误退出。
- 设置打开期间比分、球位置和计时不推进；关闭后正常恢复。
- 摄像头采集、模型加载中退出、再次进入，以及鼠标、键盘和体感模式切换均可正常使用；返回后 HUD 状态与摄像头实际状态一致。
- 结算页原有「再来一局」「返回主菜单」及键盘操作继续正常。

## 3. 降低击球难度

### 已实施

- 默认开启可关闭的手动击球辅助，玩家仍须移动和挥拍：有效期由 0.17 增至 0.30 秒模拟时间，拍面平面内距离上限由 0.12 增至 0.18 米，深度仍为 0.05 米。
- 辅助开启时仅对落台后飞向球拍的来球生效；关闭后保留原判定。键盘可覆盖完整球拍行程，挥拍提示改为来球接近球拍时显示。
- 固定输入矩阵命中由 4/24 增至 15/24；固定种子的 30 次首球对比中，指定策略的命中由 0/30 增至 30/30。这些是自动化场景，不代表真实玩家命中率，仍需实际试玩和体感摄像头验证。

### 现状和可能原因

- [constants.ts](./src/core/constants.ts) 中手动挥拍有效时间为 **0.17 秒模拟时间**、冷却为 **0.26 秒模拟时间**；拍面内的命中范围为 **0.12 米**，还要求球在球拍平面前后 0.05 米内。时间倍率和慢动作会改变对应的真实时间。
- 已有自动跟随球高、慢动作、「辅助移动」和「辅助击球」，见 [game.ts](./src/core/game.ts) 与游戏内设置。自动击球意味着玩家不再控制挥拍时机，不等同于手动挥拍容错。
- 键盘横向目标限制为 ±0.72 米，而球拍允许的行程为 ±1.0125 米；因此部分偏边来球可能比鼠标或体感模式更难接到，见 [keyboard.ts](./src/input/keyboard.ts)。
- 当前 `shouldSwing` 在球于我方半场落台后就提示挥拍，但并不保证球即将到达拍面；挥拍过早可能在球到达之前失效。
- 代码中手动命中路径目前没有检查 `playerWindowOpen` 或来球方向，尽管界面文案表示落台后才能回击；自动击球路径则检查了窗口。优化容错前应先补齐测试并确认预期规则，避免放宽后出现隔网或提前击球。
- 现有回归测试验证了模拟玩家能得分等行为，但不能代表真实玩家的接球体验；尚无针对人类输入时机和不同控制方式的量化基线。

### 备选方案

以下为实施前提出的备选方案，当前默认策略和验证结果以上方「已实施」为准。

| 方案 | 操作体验 | 注意事项 |
| --- | --- | --- |
| **建议优先评估：手动击球辅助** | 玩家仍需移动和挥拍，适度增加提前挥拍容错及横向误差容忍 | 明确显示辅助开启状态；不要扩大到球明显远离拍面时也能命中 |
| 自动挥拍 | 玩家只控制位置，适合练习走位 | 已有此选项；建议让入口更容易找到，而非重复增加功能 |
| 仅改善提示 | 更准确地提示「准备」「现在挥拍」和挥空原因 | 不改变命中判定，改善程度需实测 |

建议把辅助做成可关闭的选项，关闭时保持原有手感。不要把「挥拍灵敏度」（姿态动作识别阈值）误称为球拍命中范围。

### 实施前需确认和测量

1. 先修正或明确手动击球的合法窗口与来球方向规则，并为过早挥拍、未落台、球远离球拍、一次挥拍只能命中一次添加测试。
2. 检查键盘能否覆盖球拍合法行程，并验证边线球、输入切换及重新开始时的位置表现。
3. 用固定种子、相同来球及玩家输入轨迹对比原模式与辅助模式；记录合法来球数、主动挥拍数、命中数及过早/过晚/位置偏差等原因。
4. 先设定明确的测量目标，再确定缓冲时长与误差范围；这些数值需通过鼠标、键盘和真实摄像头试玩调校，不应仅凭自动模拟得分判断。
5. 对比辅助关闭后的相同输入和事件流，确保不改变原有弹道、得分及 AI 行为。

## 建议实施顺序

1. 先解决对局中的设置可发现性、退出确认和暂停。
2. 加入明亮球室，并保留暗色环境切换。
3. 建立击球基线、确定辅助方案与默认状态，再实现并实测手感。

上述实施内容和自动化结果见第 3 节；真实玩家的体感仍需实测。
